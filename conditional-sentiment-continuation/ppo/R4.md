
# Conditional Sentiment Continuation Model R4 (PPO)

Let's move on to R4: PPO (Proximal Policy Optimization) and complete our progression in phase 9:

- R1 — SFT: teach GPT-2 to continue a review according to a requested sentiment.
- R2 — DPO: optimize the model R1 using fixed, offline preference pairs.
- R3 — GRPO: optimize the model R1 using rewards from groups of newly generated continuations.
- R4 — PPO: optimize the model R1 using online rollouts, a reward signal, and a learned value function.

For a fair comparison, we train R4 from R1 again as R2 and R3. That way, R2, R3, and R4 are three separate post-training experiments starting from the same SFT model.

The central new concept in R4 is the value model. Unlike our GRPO experiment, PPO learns to estimate the expected future reward of a generated sequence. It uses that estimate to calculate advantages and update the policy.

We will retain the same prompt construction, reward definition, and generation settings as R3 wherever possible.

Instead of using `PPOTrainer` from Hugging Face's TRL package, we are going to implement a small, explicit PyTorch PPO model using the existing Transformers models, with our own clipped policy objective, a learned value head, generalized advantage estimation (GAE), and KL regularization. This will makes the algorithm easier to inspect, meeting our learning objectives.

**Side note**: `PPOTrainer`, `PPOConfig` and `modeling_value_head.py` along with their tests, docs and examples were dropped from TRL v1.13.0 (maybe earlier, correct me if I am wrong). For an implementation of R4 using PPOTrainer, we have to pin an earlier TRL version.

## Dataset

The PPO reward function needs three pieces of information:

- The full prompt.
- The requested sentiment.
- The original review prefix.

In R3 dataset, all these three pieces of information are already contained in a single "prompt" filed. Therefore, we reuse R3 prompt dataset by recovering the other two fileds. As a result, in the dataset for R4, there are three outstanding field: "sentiment", "prefix", and "prompt", which is the same as that in R3 dataset.

Here's an example:
```
sentiment: positive
prefix: that loves its characters and communicates something rather
prompt: Sentiment: positive\nContinue the following review:\nthat loves its characters and communicates something rather
```

## Training loop
```
                        [Prompt dataset]
            Same conditional sentiment prompts as R3
                                ↓
[Policy model]                               [Reference model]
Trainable                                       Frozen
GPT-2 R1 + value head                           GPT-2 R1
Generates continuations and predicts values     Provides the KL reference distribution
                                ↓
                    [Generated continuation]
                    Prefix + generated response
                                ↓
                    [E1 sentiment classifier]
                        Frozen reward model
            Returns the probability of the requested sentiment
                                ↓
                        [PPO optimization]
        Reward + KL penalty → advantages → policy and value updates
```

The key distinction from R3 is that PPO learns a value function to estimate expected future reward. The value head is initialized randomly and trained alongside the policy. E1 remains frozen.

## Understand the code

**R4 design**

We'll keep the same experimental task and reward definition as R3.

```
Component	        R4 implementation
--------------          -----------------
Initial policy	        R1 SFT GPT-2
Reference policy	Frozen copy of R1
Value model	        Trainable linear value head on GPT-2 hidden states
Reward model	        Frozen E1 sentiment classifier
Training data	        1,000 prompts from the R3 prompt dataset
Validation data	        100 prompts from the R3 validation dataset
Rollouts	        One sampled continuation per prompt
Reward                  E1 probability of requested sentiment
Optimization	        PPO with GAE
```

The value head is new. It takes a GPT-2 hidden state of size 768 and predicts one scalar:

```math
V(s_t)=W_v h_t+b_v
```

It learns to estimate the expected future reward from the current generation state.

The PPO update will optimize two objectives:

```math
L_{\text{policy}} =
-\mathbb{E}_t[
\min(r_t A_t,\text{clip}(r_t,1-\epsilon,1+\epsilon)A_t)
]
```

```math
L_{\text{value}} =
\frac{1}{2}\mathbb{E}_t[
\max((V_t-R_t)^2,(\text{clip}(V_t)-R_t)^2)
]
```

where $A_t$ is the GAE advantage and $R_t$ is the estimated return.

The combined loss is:
```math
L=L_{\text{policy}}+c_v L_{\text{value}}
```

Unlike GRPO, PPO uses the learned value function to estimate the baseline for each token's advantage.

**Initial hyperparameters**

We will start with a relatively conservative configuration.

```
Parameter	                Value
---------------                 -----
Training prompts	        1,000

Validation prompts	        100

Rollout batch size	        8

PPO minibatch size	        4

PPO epochs per rollout  	4

Training epochs                 1

Maximum completion length	40

Temperature                     0.9

Top-p during PPO rollouts	1.0

Learning rate	                1e-6

KL coefficient	                0.04

Policy clipping	                0.2

Value clipping	                0.2

Value loss coefficient          0.1

Gamma	                        1.0

GAE lambda	                0.95
```

One deliberate difference: we use `top_p=1.0` during PPO rollouts. This avoids introducing a top-p sampling distribution that would not be reflected in the policy log-probabilities used for the PPO ratio. We can still use the same generation parameters for all models during the eventual R0–R4 evaluation.

With 1,000 prompts and a rollout batch size of 8, we should have approximately 125 PPO updates.

We will retain the same prompt construction, reward definition, and generation settings as R3 wherever possible.

We also want the implementation to include:

- tqdm progress reporting.
- Periodic model checkpoints.
- Training reward and PPO statistics saved to a log.
- Validation reward measurements.
- A final model checkpoint that we can load for R0/R1/R2/R3/R4 comparisons.



## Metrics interpretation and model assessment

We have logged some key metrics and saved the data in `r4_training_metrics.jsonl` in `r4_checkpoints`.

From experiment results, it seems that R4 PPO has produced the most encouraging qualitative results so far, and its training reward is promising. However, its validation reward does not demonstrate an improvement over R3. We would consider R4 a successful PPO implementation and a potentially successful post-training experiment, but not yet evidence that PPO outperforms DPO or GRPO.

Here are some particularly interesting observations in the results of one run of the experiment (with initial settings as listed above).

1. PPO training metrics

Our training metrics:
```
Metric	                R4 result	Interpretation
--------------------    ---------       --------------
Mean training reward	0.6576  	Encouraging

Mean KL	                0.0023	        Small policy deviation from reference

Policy loss	        -0.0217 	Not inherently good or bad in isolation

Value loss	        0.3754	        Value function is being trained; needs further diagnostics
```

The training reward of 0.6576 is encouraging, especially compared with R3's training reward, which fluctuated around 0.62.

However, we should distinguish two things:

- PPO's training reward is calculated from newly generated training rollouts.
- Validation reward is calculated on held-out prompts.

A higher training reward is not sufficient evidence of generalization. We need to examine the validation results.

**KL is particularly interesting**

Our KL is only 0.0023.

This indicates that the policy remained quite close to the reference R1 policy. That's not necessarily bad: PPO is supposed to constrain policy updates to avoid destructive changes.

But it does raise a question: did PPO learn enough to meaningfully change the model's behavior?

Our generated examples suggest that it did learn some interesting behavior, which we'll discuss below.

2. Validation reward: R4 versus R3

This is the most important quantitative comparison we can make from the available results.

Validation mean reward

R3 — GRPO: 0.6304

R4 — PPO: 0.6274

R4 minus R3: -0.0030

R3 and R4 validation means are very close. This difference is too small to establish a meaningful performance difference.

```
Metric	                R3	R4
----------------------  ------  ------
Validation mean reward	0.6304	0.6274
Validation reward std	0.0910	0.1703
```

R4's reward standard deviation is considerably higher.

This suggests more variation in its evaluation rewards, but we would be cautious about interpreting that as greater diversity or worse consistency. The R3 evaluation generated four completions per prompt, whereas the R4 evaluation generated one per prompt. The sampling settings also differed: R3 used top-p 0.95, while R4 used top-p 1.0.

Consequently, these statistics are not a perfectly controlled comparison.

The important finding is that R4 has not demonstrated a higher validation reward than R3.

5. How PPO compares with DPO and GRPO conceptually

Now that we have completed R2, R3, and R4, we can reflect on the differences in their learning mechanisms.
```
Dimension	                DPO (R2)	        GRPO (R3)	        PPO (R4)
-----------------               ----------------------  --------------------    ---------------------
Training feedback	        Fixed preference pairs	Online group rewards	Online scalar rewards

Generates new samples    	No	                Yes	                Yes
during training

Learned value function	        No              	No	                Yes

Requires reference policy	Yes	                Yes, in our     	Yes
                                                        implementation

Advantage estimation	        Implicit in preference 	Group-relative  	GAE
                                objective

Optimization	                Preference likelihood	Group-relative policy	Clipped policy and value objectives
                                                        objective
```

The interesting distinction is how they estimate which behavior should be reinforced.

**DPO**: Given two responses to the same prompt, it learns to prefer one over the other.

**GRPO**: Given multiple responses to the same prompt, it compares their rewards and uses group-relative advantages.

**PPO**: Given a generated response, it uses the reward and learned value estimates to calculate advantages, then updates the policy using clipped probability ratios.

One subtle but important point: PPO's value function does not predict sentiment. E1 does that. The value function predicts expected future reward under the current policy.

That distinction is fundamental to understanding actor-critic reinforcement learning.

R1 — SFT	Established the conditional sentiment generation capability

## Phase 9 conclusion

This concludes our R0–R4 experiment progression

1. R0 — GPT-2 baseline
   
   Original pretrained GPT-2; no task-specific post-training.

2. R1 — SFT
   
   Learns conditional sentiment continuation from labeled examples.

3. R2 — DPO
   
   Optimizes offline preference pairs generated and scored using R1 and E1.

4. R3 — GRPO
   
   Uses online rollouts and group-relative rewards, without an independent value model.

5. R4 — PPO
   
   Current experiment
   
   Uses online rollouts, E1 rewards, a learned value function, GAE, and clipped policy optimization.

One final implementation caveat: this is an educational PPO loop, not a drop-in replacement for all the production features of TRL's PPO trainer. In particular, it does not yet implement automatic checkpoint resumption or a learning-rate scheduler. The checkpoints do save the optimizer state, so we can add resumption if needed.
