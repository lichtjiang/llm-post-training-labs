# Conditional Sentiment Continuation Model R1 (SFT)

In this lab, we post-train Vanilla GPT-2 model using SFT with a dataset adapted from SST-2 to obtain a model that not only inherits text generation capability of the base model but also learns writing styles of reviews from SST-2. Essentially, this works in the same fashion as response-only SFT that we did in ["Experiment B"](https://github.com/lichtjiang/llm-post-training-labs/blob/main/child-dialogue-lm/response-only-sft/sft_childes_gpt2_experiment_b.md)


R1 will be the foundation for R2 (DPO), R3 (GRPO), and R4 (PPO), so we would treat its output as a reusable model artifact, not just a model that happens to finish training.

We would implementing R1 with plain PyTorch + Hugging Face Transformers, with a lazy dataset generator built from SST-2. We'll simply use full GPT-2 fine-tuning for this first experiment, without any quantization like we did in phase 5 (LoRA) and phase 6 (QLoRA).

The training objective is:

```math
\mathcal{L}_{SFT}
=
-\sum_{t \in \text{completion}}
\log P_\theta(x_t \mid x_{\text{<}t})
```

In other words, GPT-2 sees both the sentiment instruction and the review prefix, but its loss is calculated only on the completion and EOS token.


## Learning Objectives

- response-only loss masking
- understand the difference between attention_mask and label/loss mask
- lazy generation of datasets

## Why R1

As mentioned above, we build R1 (SFT) as the base model so that we can study how to apply three different reinforcement learning (RL) algorithms later, namely, DPO, GRPO, and PPO. This step is essential. Remember, RL targets at maximizing cumulative rewards instead of forcing a model to follow certain known behaviors (such as writing style of SST-2 reviews), unless it happens to align with the RL goal. Therefore, if we directly fine tune GPT-2 with RL, we most probably would not see generated text look like online reviews (SST-2 reviews created from Rotten Tomatoes) even it may perfectly match a requested sentiment.

## Dataset

Recall that an example in SST-2 looks like the following:

```
"contains no wit , only labored gags", 0
"the greatest musicians", 1
```

That is, each example consists of a `sentence` and its `label` (0 for "negative" and 1 for "positive").

We split the sentence at a word boundary, e.g., around 60% of its length.

So, for this positive review:

    A wonderfully funny and entertaining movie with a great cast and a heartwarming story.

After splitting, we will have the following two parts:

Prompt prefix:
    A wonderfully funny and entertaining

Target continuation:
    movie with a great cast and a heartwarming story.

We then construct the training prompt:

```
Sentiment: positive
Continue the following review:
A wonderfully funny and entertaining
```


And the target response:
```
movie with a great cast and a heartwarming story.
```

For a negative SST-2 example, we do exactly the same thing, except the instruction says `Sentiment: negative`.

In other words, the original dataset:

    sentence + sentiment label

becomes:

    sentiment instruction + sentence prefix → target continuation

This is a straightforward transformation, and it doesn't require generating synthetic text.

Considering that SST-2 contains short and incomplete sentences, to ensure data quality, we establish a few simple filtering rules in this process.

```
Rule                                Suggested starting point
--------------------------------    ------------------------
Minimum original sentence length    8 words

Minimum prompt prefix               4 words

Minimum target continuation         3 words

Split position                      Randomly between 50% and 70%

Splits per original sentence        1
```

These are starting values, not universal requirements. We can inspect the resulting dataset and adjust them.

We would prefer filtering out short examples rather than trying to manufacture continuations for them.

There is another subtlety: some review sentences are grammatically incomplete even in the original dataset. That's acceptable for our task. We are training a model to continue a piece of text, not to write a complete review from scratch.

A few important implementation details:

- Set a fixed random seed so the generated dataset is reproducible.
- Split the original SST-2 dataset before generating continuations. Never allow different fragments of the same original sentence to appear in both training and validation.
- Use the original validation set for validation.
- Don't depend on the SST-2 test labels, which are not publicly available in the same way as the training labels.
- Inspect a sample of generated examples manually before training.

The resulting dataset will look like:

```json
{
    "prompt": (
        "Sentiment: positive\n"
        "Continue the following review:\n"
        "A wonderfully funny and entertaining"
    ),
    "completion": (
        " movie with a great cast and a "
        "heartwarming story."
    ),
    "sentiment": "positive"
}
```

**Important**: for GPT-2 SFT in this lab, we concatenate the prompt and completion, tokenize them, and mask the prompt portion of the labels with -100, just as we did in our earlier response-only SFT experiment.

**Lazy creation**

We transform SST-2 examples on demand, without constructing and storing a second dataset in memory or saving anything to disk; we separate the transformation of an individual SST-2 example from the generator that iterates over the dataset. This makes the code easier to test and reuse.

Our dataset creation flow will be:
```
        SST-2 dataset
       sentence + label
              ↓
        Python generator
    Iterate over examples lazily
              ↓
        Transform each example
Filter → split → construct prompt/completion
              ↓
    Yield one training example
   prompt + completion + sentiment
```

**Reproducibility**

We use a local random.Random(seed) instance instead of Python's global random generator. This means the split positions are reproducible and independent of random operations elsewhere in our training code.

For validation, we also use a fixed seed, so the same original sentence always produces the same prefix/completion split.

**Tokenization is separate from dataset**

Our dataset is created on demand on words, not GPT-2 tokens, while prompt and completion tokenize comes later before training `R1` using the GPT-2 tokenizer and construct:

```python
input_ids = prompt_tokens + completion_tokens

labels =
    [-100, -100, ..., -100] + completion_tokens
```

The prompt is context; only the completion contributes to the SFT loss.

Handling our dataset creation this way allows us to manually manage PyTorch training loops instead of working with Hugging Face Trainer. That also keeps the mechanics transparent.


## R1 model architecture

This is indeed just the Vanilla GPT-2.

```
GPT2LMHeadModel(
  (transformer): GPT2Model(
    (wte): Embedding(50257, 768)
    (wpe): Embedding(1024, 768)
    (drop): Dropout(p=0.1, inplace=False)
    (h): ModuleList(
      (0-11): 12 x GPT2Block(
        (ln_1): LayerNorm((768,), eps=1e-05, elementwise_affine=True, bias=True)
        (attn): GPT2Attention(
          (c_attn): Conv1D(nf=2304, nx=768)
          (c_proj): Conv1D(nf=768, nx=768)
          (attn_dropout): Dropout(p=0.1, inplace=False)
          (resid_dropout): Dropout(p=0.1, inplace=False)
        )
        (ln_2): LayerNorm((768,), eps=1e-05, elementwise_affine=True, bias=True)
        (mlp): GPT2MLP(
          (c_fc): Conv1D(nf=3072, nx=768)
          (c_proj): Conv1D(nf=768, nx=3072)
          (act): NewGELUActivation()
          (dropout): Dropout(p=0.1, inplace=False)
        )
      )
    )
    (ln_f): LayerNorm((768,), eps=1e-05, elementwise_affine=True, bias=True)
  )
  (lm_head): Linear(in_features=768, out_features=50257, bias=False)
)

```

## Understand the Code


**R1 configuration**
```
Setting                     Value
----------                  ---------------------
Base model                  openai-community/gpt2

Model architecture          GPT2LMHeadModel

Training data               Transformed SST-2

Training examples           Up to 10,000 before filtering

Validation data             Transformed SST-2 validation split

Training epochs             1

Maximum sequence length     128 tokens

Batch size                  4

Learning rate	            5e-5

Weight decay	            0.01

Loss	                    Causal language-model cross-entropy

Trainable parameters	    All GPT-2 parameters
```

We've chosen a conservative learning rate for full-model fine-tuning. We can increase the number of epochs later if the results suggest underfitting.

Batch size 4 and sequence length 128 are chosen for fine tuning GPT-2 124M on a 16GB machine. Adjust these settings when necessary.

**GPT-2 shifts labels internally**

We supply labels aligned with the input sequence. GPT2LMHeadModel internally shifts them so that the logit at position \(t\) predicts the token at position \(t+1\).

Therefore, we must not manually shift the labels before passing them to the model.

**Padding and EOS share the same token ID**

We set:
```python
tokenizer.pad_token = tokenizer.eos_token
```

But our collator constructs the attention mask from sequence lengths, rather than comparing token IDs. Otherwise, genuine EOS tokens could mistakenly be masked as padding.

**The prompt is excluded from the loss, not from attention**

This is particularly important:
```python
labels = (
        [-100] * len(prompt_ids)
        + completion_ids
)
```

The prompt remains visible to GPT-2 through its attention mechanism. We simply don't ask the model to learn to reproduce the prompt.

**Checkpoints organization**

After training, our directory will look like this:
```
r1_checkpoints/
│

│   ├── config.json
│   ├── model.safetensors

│   └── training_metadata.json
│
├── r1-sft-best/
│   ├── config.json

│

    ├── ...
```

The periodic checkpoints are saved every 2,000 optimizer steps. The best checkpoint is selected using validation loss.

These checkpoints contain the model weights, configuration, and tokenizer. They are sufficient for loading the model into R2, R3, and R4. They do not contain optimizer state for resuming the exact interrupted training run; we don't need that for our planned experiments.

For this first one-epoch experiment, r1-sft-best and r1-sft-final should contain the same weights.

**Loading R1 model later for R2, R3, and R4**
```python
from transformers import (
    AutoTokenizer,
    GPT2LMHeadModel,
)

R1_MODEL_PATH = "./r1_checkpoints/r1-sft-best"

loaded_tokenizer = AutoTokenizer.from_pretrained(
    R1_MODEL_PATH
)

loaded_model = GPT2LMHeadModel.from_pretrained(
    R1_MODEL_PATH
)

device = torch.device(
    "cuda" if torch.cuda.is_available()
    else "mps" if (
        hasattr(torch.backends, "mps")
        and torch.backends.mps.is_available()
    )

loaded_model.to(device)
loaded_model.config.use_cache = True
loaded_model.eval()
```
Notice that we load from the best checkpoint directory, not from the original GPT-2 model repository. This ensures that subsequent experiments start from the best R1 SFT weights.

```math

```

Again, though contributing to the polarity of the whole reivew, prompt tokens do not contribute to SFT loss.
